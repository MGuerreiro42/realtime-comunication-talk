Polling

  • Como funciona: cliente chama GET a cada N segundos
  • Conexoes: 1 nova por tick
  • Latencia: ate N segundos
  • Overhead: alto — requisicoes mesmo sem dados novos
  • Uso: dashboards simples, compatibilidade maxima

Long Polling

  • Como funciona: cliente abre requisicao, servidor segura ate ter dados
  • Conexoes: 1 por evento (reconecta automaticamente)
  • Latencia: quase zero — responde assim que ha dado
  • Overhead: medio — reconexao a cada evento
  • Uso: chat, notificacoes (pre-SSE/WS)

Server-Sent Events

  • Como funciona: HTTP stream persistente, server → client
  • Conexoes: 1 unica (reconnect automatico pelo browser)
  • Latencia: quase zero
  • Overhead: baixo — so HTTP headers uma vez
  • Uso: feeds ao vivo, logs, notificacoes push

WebSocket

  • Como funciona: upgrade TCP full-duplex (ws://)
  • Conexoes: 1 unica, persistente
  • Latencia: minima — frames binarios
  • Overhead: muito baixo apos handshake
  • Uso: jogos, colaboracao ao vivo, trading, chat
